# Face Color Match v0.6.0

Photoshop JSX + локальный Python-инструмент для приведения цвета кожи к заранее измеренному эталонному пресету.

Документ Photoshop всё время остаётся в RGB. Python использует Lab только как внутреннее математическое пространство для расчёта плавной цветовой коррекции, после чего результат снова преобразуется в обычный RGB→RGB LUT.

## Текущая архитектура

```text
Исходный RGB
    ↓
Global White Balance
    ↓
Smooth Tone
    ↓
Smooth Skin Color (Lab model → RGB LUT)
    ↓
Residual LUT — только в расширенном режиме и только при реальной пользе
```

Итоговые редактируемые слои Photoshop могут выглядеть так:

```text
ΔE 5.2→2.1 — Face Color Match — preset
├─ Residual LUT ΔE 2.3→2.1       # только при необходимости
├─ Skin Color ΔE 4.0→2.3
├─ Tone ΔE 4.4→4.0
└─ White Balance ΔE 5.2→4.4      # только если безопасен и полезен
```

Бесполезные этапы не создаются.

## Что изменилось в v0.5.0

- Удалён отдельный Hue/Saturation: насыщенность больше не корректируется независимым глобальным инструментом.
- Parametric colour curves удалены из рабочего алгоритма. Глобальный этап Tone теперь отвечает главным образом за яркость и использует только Composite Curve.
- Цвет кожи рассчитывается в Lab как плавная функция `Δa(L)` / `Δb(L)`, но Photoshop получает обычный RGB→RGB Color Lookup.
- Skin Color строится по более плотному набору тональных измерений: 11 уровней вместо 5 для новых пресетов.
- Старые пресеты остаются совместимыми: исходные quantile 0.12 / 0.30 / 0.50 / 0.70 / 0.88 сохранены среди новых измерений.
- Кривые `Δa` и `Δb` сглаживаются регуляризацией второго порядка, поэтому отдельные зоны лица не создают резких переломов.
- Skin LUT локализован по реальному skin-gamut: учитываются эллиптическое расстояние в a/b, расстояние до измеренных skin samples, светлота, защита нейтралей, теней и почти белых значений.
- Для Skin Color выполняется leave-one-zone-out validation: одна зона лица исключается из построения модели и используется как проверочная.
- Выбирается самая слабая сила Skin Color, сохраняющая примерно 90% лучшего подтверждённого выигрыша.
- Global White Balance принимается только если средний ΔE улучшается, не менее 70% взвешенных измерений не ухудшаются и отдельно защищены обе щеки.
- Residual LUT теперь действительно residual: диапазон Lab-поправок уменьшен, влияние уже, максимальная сила ограничена 0.5.
- Единый `Мин. улучшение ΔE` продолжает действовать для каждого этапа.
- Родная сетка LUT остаётся 17×17×17; пересчёта в 40³ нет.
- Временные `.cube` и `.icc` удаляются сразу после успешного встраивания в Color Lookup.
- Предпросмотр для Python остаётся JPEG для быстрой передачи больших документов.

## Режимы

### Smooth

Создаёт только действительно полезные этапы:

1. безопасный Global White Balance;
2. Smooth Tone;
3. Smooth Skin Color.

### Smooth + Fine Tune

Выполняет тот же Smooth Match и затем проверяет слабый residual LUT. Residual создаётся только если дополнительное уменьшение ΔE превышает установленный порог и большинство измерений не ухудшается.

## Параметры главного окна

**Пресет** — эталон измеренного цвета кожи.

**Режим** — `Smooth` либо `Smooth + Fine Tune`.

**Сила** — непрозрачность всей итоговой группы Photoshop. Расчёт ΔE выполняется для 100% силы; уменьшение opacity вручную меняет фактический визуальный результат.

**Мин. улучшение ΔE** — минимальный полезный выигрыш отдельного этапа. По умолчанию `0.1`. Если этап улучшает измеренный ΔE меньше этого значения, слой не создаётся.

## Настройки

**Папка пресетов** — каталог JSON-пресетов.

**Размер анализа, px** — максимальная сторона JPEG-превью, передаваемого Python. Значение `1400` обычно является хорошим балансом скорости и точности.

**Корректировать тон (яркость)** — разрешает Smooth Tone создавать Composite Curve. При отключении глобальная тональная коррекция пропускается.

**Пропускать изображение, если лицо не найдено** — удобно при пакетном запуске через Photoshop Actions.

**Имя слоя** — базовое имя итоговой группы.

## Пресеты

При создании нового пресета:

- лицо нормализуется по landmarks YuNet;
- основные измерения берутся со щёк, лба, носа и подбородка;
- щеки имеют максимальный вес;
- пиксели фильтруются относительно индивидуального skin-кластера;
- новые пресеты получают 11 тональных quantile для более устойчивого плавного fit;
- гистограмма всего кадра используется только для построения глобальных Curves.

После крупных изменений алгоритма рекомендуется пересоздать наиболее важные эталонные пресеты, хотя старые пресеты v0.4.x остаются совместимыми.

## Photoshop Actions

Поддержка Actions включена всегда.

При записи шага сохраняются:

- `preset_id`;
- режим;
- минимальное улучшение ΔE;
- настройка Tone;
- сила группы;
- имя группы;
- поведение при отсутствии лица.

При обычном playback интерфейс не показывается. Для показа интерфейса используется штатный переключатель диалога шага Action в Photoshop.

## Python

Используется системный CPython 3.11 или 3.14. Выбор версии в интерфейсе отсутствует: пользователь устанавливает нужную среду один раз через соответствующий BAT, а JSX автоматически запускает доступный поддерживаемый вариант.

Зависимости:

- NumPy;
- OpenCV headless;
- YuNet face detector model.

Дополнительные библиотеки вроде SciPy не требуются.

## Временные файлы

- JPEG анализа удаляется после ответа Python.
- `.cube` и `.icc` Skin Color / Residual удаляются после успешного создания Color Lookup.
- Если импорт LUT завершается ошибкой до успешного встраивания, исходная ошибка передаётся основному JSX.

## Важное про ΔE

ΔE используется как контрольная метрика, но алгоритм больше не пытается минимизировать её любой ценой.

При близком результате предпочтение отдаётся:

- более слабой коррекции;
- более гладкой функции;
- меньшему изменению теней;
- лучшему результату на validation-зонах;
- меньшему числу корректирующих этапов.


## v0.6.0 — Tone только по светлоте

Tone больше не оптимизируется по RGB или цветовой ошибке как по целевой величине.

1. Target/reference переводятся в Lab.
2. Tone анализирует только `L*`.
3. Вычисленная светлотная поправка выражается обычной Composite RGB Curve Photoshop.
4. Цвет (`a/b`) остаётся задачей Skin Color.

Чтобы исключить "ломаные" кривые:

- в Tone всего **две внутренние точки**: RGB 128 и RGB 205;
- `(0,0)` и `(255,255)` всегда фиксированы;
- midtone ограничен `±7`;
- highlights ограничены `±12`;
- движение примерно в RGB 48 ограничено `±3`;
- контролируется диапазон наклонов и максимальный перелом между сегментами;
- выбирается самая слабая сила, сохраняющая около 90% лучшего улучшения L*;
- при отсутствии безопасного выигрыша Tone вообще не создаётся.

Режимы переименованы в:

- `Smooth`;
- `Smooth + Fine Tune`.

`Fine Tune` — дополнительный слабый residual LUT после основной Smooth-коррекции.
