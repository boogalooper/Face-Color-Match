# Face Color Match v0.1.7

Экспериментальный Photoshop JSX-скрипт для автоматического сведения цвета портретов к заранее измеренному образцу. Результат создаётся как обычный **Curves Adjustment Layer** с отдельными R/G/B-кривыми и, при необходимости, мягкой общей RGB-кривой. Исходное изображение не изменяется Python-кодом.

## Структура

```text
Face Color Match.jsx
install_python311.bat
install_python314.bat
lib/
  face-color-api.pyw
  models/
    face_detection_yunet_2023mar.onnx   # скачивается установщиком
```

Python-сервер однофайловый, работает с **системным Python** и не создаёт `venv`. JSX запускает его автоматически при необходимости. После 30 минут бездействия сервер завершает работу; во время последовательной обработки Photoshop Actions таймер постоянно обновляется.

## Установка

1. Установите обычный CPython **3.11** или **3.14** с `python.org`. Желательно оставить включённым **Python Launcher for Windows**.
2. Один раз вручную запустите соответствующий файл:
   - `install_python311.bat`, или
   - `install_python314.bat`.
3. Скопируйте папку скрипта в удобное место в `Presets/Scripts` Photoshop либо храните JSX вместе с подпапкой `lib` в другом месте, откуда вы обычно запускаете JSX.
4. Перезапустите Photoshop, если хотите видеть скрипт в меню `File > Scripts`.

Установщик сначала проверяет существующие `cv2` и `numpy`. Если они уже подходят, он не заменяет их. В противном случае ставится проверенная связка пакетов. Установщик также пытается скачать небольшой YuNet ONNX-модель детектора лица. Если загрузка модели не удалась, скрипт использует встроенный Haar fallback, но точность локализации лица будет ниже.

## Первый пресет

1. Откройте фотографию-образец в Photoshop.
2. Запустите `Face Color Match.jsx`.
3. Нажмите `+` рядом со списком пресетов.
4. Введите имя образца.
5. Скрипт создаст уменьшенную сведённую sRGB-копию только для анализа, Python измерит устойчивые зоны кожи и сохранит JSON-пресет.

По умолчанию пресеты сохраняются в `Documents/Face Color Match Presets`. Папку можно изменить через `⚙`. В Photoshop Actions записывается **стабильный `preset_id`**, а не абсолютный путь, поэтому папку пресетов можно перенести и затем один раз указать новое расположение в настройках.

## Применение

1. Откройте целевое фото.
2. Выберите пресет.
3. Выберите режим:
   - **Точные кривые** — более свободная оптимизация при сохранении монотонности и фиксированных концов кривой;
   - **Безопасные кривые** — более сильное ограничение на изгиб и величину коррекции.
4. Нажмите `ПРИМЕНИТЬ`.

Скрипт создаёт один корректирующий слой `Curves`. Количество внутренних точек на канал — `Авто`, `2`, `3` или `4`. Чёрная и белая точки всегда остаются `0→0` и `255→255`. Параметр **Сила** реализован непрозрачностью корректирующего слоя, поэтому сама рассчитанная кривая сохраняется без дополнительной математической деформации.

## Photoshop Actions

Скрипт рассчитан на запись в Action.

1. Начните запись Action.
2. Запустите скрипт **из Photoshop** через `File > Scripts > Face Color Match` (или `File > Scripts > Browse…`). Запуск из VS Code/ExtendScript debugger не создаёт вызываемый Photoshop menu-step и не должен использоваться для записи Action.
3. Выберите пресет и настройки и примените коррекцию.
4. Остановите запись.

При обычном воспроизведении Action интерфейс скрипта не показывается: используются параметры из `app.playbackParameters`. Если включить стандартный значок диалога у шага Action, интерфейс будет открыт; **Shift** также принудительно открывает его для текущего запуска. Это позволяет применять коррекцию через стандартный Photoshop Batch, Image Processor или сторонние пакетные сценарии.

Опция `Записывать рабочие настройки в Photoshop Action` включена по умолчанию. Папка пресетов, версия системного Python и размер временного анализа остаются глобальными настройками и не дублируются внутри Action.

## Что измеряет v0.1

Python:

- находит главное лицо YuNet (или Haar fallback);
- при YuNet выравнивает масштаб и наклон лица по 5 landmarks перед измерением;
- измеряет лоб, обе щеки, нос и подбородок;
- исключает области глаз и рта, когда доступны landmarks YuNet;
- выполняет устойчивое отбрасывание цветовых выбросов;
- строит несколько тональных контрольных точек внутри каждой зоны;
- сравнивает соответствующие зоны и тональные диапазоны с JSON-пресетом;
- подбирает монотонные RGB Curves с 2–4 внутренними точками;
- считает диагностический `ΔE00` до и после рассчитанной коррекции.

В `⚙` можно включить показ диагностики после ручного запуска.

## Ограничения текущей версии

Это первая рабочая архитектурная версия. Она специально не использует генеративную нейросеть и не меняет пиксели оригинала в Python. Глобальные Curves принципиально не могут исправить локально разное освещение на разных участках лица. Кроме того, алгоритм пока выбирает крупнейшее/наиболее центральное лицо и рассчитан прежде всего на одиночные портреты.

Если Curves окажутся недостаточными на реальных сериях, следующая логичная ветка — 3D LUT fallback и/или более точная сегментация кожи, сохранив тот же JSX ↔ Python протокол и систему пресетов.

## Временные файлы и логи

Временный PNG создаётся только для анализа, после ответа Python удаляется JSX. Лог сервера находится во временной папке Windows под именем `face-color-match.log`.

## Изменения v0.1.4

- Полностью переработан подбор Curves: вместо свободной глобальной оптимизации используются общие тональные опоры лица — тени, средние тона и света; четвёртая точка добавляется только при заметной пользе.
- В режиме Auto сначала строится наиболее простая двухточечная коррекция; дополнительные точки принимаются только если они дают заметное снижение остаточной ΔE.
- Добавлен параметр `Допуск совпадения ΔE` (по умолчанию 2.0): алгоритм намеренно не пытается свести цвет математически в ноль и оставляет небольшой допустимый остаток, чтобы коррекция не становилась агрессивной.
- Коррекция около границы допуска ослабляется плавной степенной функцией; чем меньше ошибка, тем слабее воздействие.
- Вертикальные смещения точек регуляризуются как единая плавная функция. Дополнительно ограничены отклонение наклона от диагонали, изменение наклона между соседними сегментами и максимальное смещение точки.
- Общая RGB-кривая теперь выключена по умолчанию и, если включена вручную, выполняет только мягкую частичную коррекцию яркости перед каналами R/G/B.
- Старые настройки автоматически мигрируют на новую безопасную схему; существующие JSON-пресеты образцов пересоздавать не требуется.
- Новый параметр допуска записывается в Photoshop Action вместе с остальными рабочими настройками.


## Изменения v0.1.5 — histogram-aware curves

- Положение корректирующих точек больше не берётся непосредственно из тональных выборок кожи. Цвет измеряется по коже, а **X-координаты точек выбираются по гистограмме всего изображения**, как при ручной работе с Curves.
- Базовые точки располагаются в областях **теней и светов**, преимущественно во впадинах между заметными пиками сглаженной гистограммы.
- Средняя точка добавляется только при наличии реальной гистограммной впадины; четвёртая точка ещё строже считается необязательной.
- `Авто` и значения `2/3/4` теперь означают **максимальное** число внутренних точек: скрипт не создаёт лишнюю точку ради выполнения заданного количества.
- Минимальная дистанция между внутренними точками увеличена примерно до 30–34 уровней; тесные пары точек запрещены.
- Вертикальный сдвиг, отклонение наклона от диагонали и изменение изгиба дополнительно ограничены. `Precise` теперь означает более точный выбор мест коррекции, а не более агрессивную кривую.
- Для переноса измеренной цветовой ошибки кожи на удалённую гистограммную впадину используется **степенное затухание по расстоянию**. Поэтому точка между пиками мягко и косвенно воздействует на сами пики.
- Существующие JSON-пресеты совместимы: пересоздавать образцы для v0.1.5 не требуется.


## Изменения v0.1.6 — сильные различия и экспозиция

- Исправлено систематическое недокорректирование при большом ΔE: положение точек по-прежнему выбирается в безопасных впадинах гистограммы, но их вертикальный сдвиг теперь решается напрямую через интерполяцию Curves методом взвешенных наименьших квадратов.
- Точка между пиками теперь сдвигается настолько, насколько нужно для воздействия на реальные значения кожи через плавную интерполяцию; прежнее затухание по расстоянию, из-за которого требовалось 4–6 повторных запусков, удалено.
- `Precise curves` адаптивно допускает более сильное общее смещение при большом ΔE, но продолжает ограничивать локальные переломы и сохраняет большое расстояние между контрольными точками.
- `Safe curves` остаётся заметно более консервативным.
- Общая RGB-кривая теперь является отдельным этапом коррекции **яркости/экспозиции**, а не цвета, и включена по умолчанию.
- Коррекция общей RGB-кривой рассчитывается непосредственно по разнице яркости образца и текущего лица и больше не ослабляется множителем от цветового ΔE.
- В диагностике добавлена ошибка яркости до/после.
- Имя создаваемого слоя получает префикс `ΔE исходное→после`, например `ΔE 12.8→2.6 — Face Color Match — Образец`.
- При обновлении JSX автоматически завершает оставшийся в памяти Python-сервер предыдущей версии и запускает сервер той же версии, что и JSX; ждать 30-минутного idle-timeout больше не нужно.
- Старые JSON-пресеты совместимы и не требуют повторного измерения.


## Исправления v0.1.7

- Гистограмма для постановки точек Curves теперь измеряется по всему изображению, а не по нормализованному crop лица.
- Измерение цвета кожи ужесточено: используются seed-области щёк/лба, затем остальные пиксели фильтруются по близости к skin-кластеру в Lab.
- Пересмотрены веса зон лица: приоритет у щёк; нос, подбородок и лоб влияют слабее.
- Пересмотрены веса тональных групп: глубокие тени влияют заметно меньше, светлая кожа — сильнее.
- В модель пресета добавлена оценка качества измерения (`quality.score`), чтобы можно было видеть сомнительные образцы.
