# Face Color Match v0.9.5

Photoshop JSX + локальный Python-инструмент для приведения цвета кожи к заранее измеренному эталонному пресету.

Документ Photoshop остаётся RGB. Python использует Lab только как внутреннее математическое пространство для анализа и расчёта; Photoshop получает обычные Curves и один RGB→RGB Color Lookup.

## Архитектура

```text
Исходное изображение
    ↓
Global White Balance     # только если безопасен и полезен
    ↓
Smooth Tone              # только если безопасен и полезен
    ↓
Skin Match               # один итоговый 33³ LUT
```

Внутри **Skin Match** объединены:

- гладкая `ΔL*(L*)`;
- гладкая `Δa(L*) / Δb(L*)`;
- слабый локальный chroma-RBF;
- автоматический chroma-only refinement — прежний Fine Tune.

Отдельного режима и отдельного слоя Fine Tune больше нет. Refinement проверяется всегда и, если улучшает результат безопасно, сразу запекается в тот же итоговый Skin Match LUT.

## Почему удалён выбор режима

Пользователю больше не нужно решать, запускать ли Fine Tune. Алгоритм сам проверяет дополнительную доводку на каждом изображении.

В Photoshop остаётся максимум три преобразования:

```text
White Balance
Tone
Skin Match
```

WB и Tone создаются только при реальной пользе. В некоторых кадрах остаётся только Skin Match.

## Защита тонального рисунка лица

### Tone

Tone — одна гладкая Composite RGB Curve:

- чёрная и белая точки фиксированы;
- функция определяется только midtone/highlight параметрами;
- Photoshop получает плотную выборку одной и той же функции;
- контролируются наклон и изменение наклона;
- положительное осветление глубоких теней дополнительно штрафуется;
- около RGB 48 положительный сдвиг ограничен примерно `+1.35`.

### Светлота внутри Skin Match

`L*` больше не имеет локального RBF-residual.

Светлотная часть:

- является только одномерной функцией от исходной `L*`;
- сглаживается;
- ограничивается по производной `d(ΔL*)/dL*`;
- не получает локальных многомерных поправок;
- положительная локальная коррекция в тенях почти полностью подавляется и плавно возвращается от `L*=46` до `L*=64`.

Локальный RBF и внутренний refinement работают только с `a/b`, поэтому уточняют цвет, не создавая локальных перепадов яркости.

## Global White Balance

WB остаётся отдельным глобальным этапом, поскольку может исправлять общий сдвиг всего кадра.

Он применяется только если:

- уменьшает измеренный ΔE;
- большая часть измерений не ухудшается;
- отдельно не ухудшается левая или правая щека.

Photoshop получает плотную выборку той же гладкой WB-функции, которую оценивал Python.

## Skin Match

Основной Skin Match использует native **33×33×33** LUT.

Сила выбирается по фактическому дискретному LUT — тому же преобразованию, которое затем получает Photoshop.

При выборе учитываются:

- уменьшение ΔE;
- stratified cross-validation;
- доля неухудшившихся измерений;
- влияние LUT на реальные пиксели вне расширенной области лица.

Collateral-анализ в основном является мягким штрафом. Жёсткий запрет применяется только при явно чрезмерном spill.

## Внутренний refinement

После основной коррекции автоматически рассчитывается chroma-only residual.

Он:

- не имеет отдельного режима;
- не создаёт второй Photoshop-слой;
- не меняет `L*`;
- сохраняется только при дополнительном безопасном улучшении;
- запекается в итоговый 33³ Skin Match LUT.

## Главное окно

**Пресет** — эталон цвета кожи.

**Сила** — opacity всей итоговой группы. ΔE рассчитывается для 100% силы.

**Мин. улучшение ΔE** — минимальный полезный выигрыш отдельного этапа. По умолчанию `0.1`.

## Настройки

Под шестерёнкой остаются:

- папка пресетов;
- размер анализа;
- пропуск изображения при отсутствии лица;
- имя итоговой группы.

Выбор режима, версии Python, запись в Action и отдельное включение Tone отсутствуют.

## Photoshop Actions

Поддержка Actions включена всегда.

Записываются:

- `preset_id`;
- минимальное улучшение ΔE;
- сила группы;
- имя группы;
- поведение при отсутствии лица.

Старые дополнительные поля предыдущих версий игнорируются.

## Python

Поддерживаются системные CPython 3.11, 3.12, 3.13 и 3.14.

Зависимости:

- NumPy;
- OpenCV headless;
- YuNet face detector model.

При отсутствии YuNet используется менее точный Haar fallback.

## Пресеты

Новые пресеты используют 11 тональных quantile. Старые пресеты с 5 историческими quantile остаются совместимыми.

## Временные файлы

JPEG/CUBE/ICC являются только транспортными файлами и удаляются после использования. Остатки аварийно прерванной предыдущей сессии очищаются при следующем запуске.

## Ограничение цветового пространства

Предпросмотр для Python переводится Photoshop в sRGB. Для максимально предсказуемого совпадения рекомендуется использовать sRGB-документы. Для Adobe RGB/ProPhoto и других RGB-профилей итоговый LUT требует отдельной цветоуправляемой адаптации; эта задача не решается в v0.8.0.


## v0.8.1 — smooth saturation control

- Added explicit smooth saturation matching inside Skin Match via a lightness-dependent `ΔC*(L*)` component.
- Chroma is now split into radial saturation correction plus a smaller residual `Δa/Δb` hue component.
- This helps when hue is already close but the skin is noticeably too gray or too saturated compared with the preset.
- The local RBF and internal refinement remain chroma-only and still do not modify `L*`.
- No new UI switch was added: saturation correction is applied automatically only as part of the same unified Skin Match LUT.


## v0.8.2 — progress при запуске Python-сервера

Если совместимый локальный Python-сервер уже запущен, запуск остаётся мгновенным и никакое дополнительное окно не показывается.

Если сервер отсутствует или требуется перезапустить сервер другой версии, Photoshop показывает небольшой progress palette со стадиями:

- подготовка запуска;
- запуск Python;
- загрузка Python / OpenCV / NumPy;
- ожидание локального API;
- проверка соединения.

Progress показывается даже при тихом запуске из Photoshop Action, потому что именно первый запуск Python иначе может выглядеть как зависание Photoshop.

Алгоритм цветокоррекции v0.8.1 в этой версии не изменён.


## v0.8.3 — более равномерная коррекция теней

Smooth Tone получил один дополнительный, строго ограниченный **shadow parameter**.

Это не новая свободная точка Photoshop Curves. Tone по-прежнему является одной гладкой функцией, которую Python плотно сэмплирует перед передачей Photoshop.

Новая модель Tone имеет всего три степени свободы:

- shadow — максимум около `±4` уровней в центре теневого диапазона;
- midtone — прежний диапазон;
- highlights — прежний диапазон.

Shadow-функция:

- равна нулю в абсолютном чёрном;
- плавно достигает максимума около RGB 64;
- снова плавно становится нулевой к RGB 128;
- поэтому не меняет black point и не создаёт отдельного излома на границе теней.

Дополнительные защиты:

- около RGB 32 итоговый сдвиг ограничен примерно `±2.5`;
- около RGB 48 — примерно `±3.8`;
- сохраняются ограничения общей монотонности, наклона и bend кривой;
- убран прежний дополнительный штраф именно за **осветление** теней, из-за которого алгоритм был асимметричен;
- в оптимизацию добавлена небольшая отдельная оценка ошибки `L*` в тенях, чтобы реальные тёмные skin measurements не терялись из-за их небольшого общего веса.

Защита Skin Match от **локального** осветления теней сохранена. То есть глобально осветлить тени теперь должен Smooth Tone, а не локальный RBF/LUT.

Progress запуска Python-сервера из v0.8.2 сохранён.


## v0.9.0 — управление тенями/светами, безопасностью и более аккуратная история

- На главный экран вынесены два новых слайдера: **Тени / света** и **Точность / защита**.
- Оба слайдера имеют понятные `helpTip` и «мёртвую зону» около **Auto**, как в img2img helper.
- Скрипт больше не дублирует документ ради анализа: JSX сохраняет безопасную JPEG-копию через **Save a copy**, а Python сам уменьшает её до заданного размера анализа.
- Все промежуточные действия применения коррекции в Photoshop теперь объединены в **одну запись истории** через `suspendHistory`.
- Новые параметры записываются в Photoshop Action вместе с остальными настройками запуска.


## v0.9.1 — исправление запуска и читаемые метрики

- Исправлена ошибка `name 'lightness_balance' is not defined` при начале обработки: тональный вес теперь применяется только внутри расчёта Tone, а общий ΔE снова считается независимо.
- В имени Tone теперь отображается последовательный общий `ΔE` **до→после Tone**, а `ΔL*` оставлен второй метрикой: `Tone ΔE 6.9→5.8 · ΔL* 8.1→6.7`.
- Справа от новых слайдеров отображается только числовое значение (`-35`, `0`, `+35`), без длинных подписей.
- Мёртвая зона `±8` около Auto повторяет логику ползунка resize из img2img helper: магнит к нулю работает при перетаскивании мышью, а клавиши меняют значение точно по 1.
- `suspendHistory` исправлен по архитектуре img2img helper: callback вынесен в глобальную область, поэтому создание всей группы коррекции действительно попадает в одну запись истории Photoshop.
- Нейтральное положение `Точность / защита = 0` теперь точно сохраняет защитные пороги v0.8.3; слайдер изменяет их только при отклонении от центра.


## v0.9.2 — Python 3.11–3.14

Ограничение на две конкретные версии Python снято.

Теперь поддерживаются:

- Python 3.11;
- Python 3.12;
- Python 3.13;
- Python 3.14.

При автоматическом запуске сервер ищет подходящий интерпретатор в порядке
`3.14 → 3.13 → 3.12 → 3.11`, отдавая предпочтение версии, где уже установлены
NumPy и OpenCV.

Добавлен единый `install.bat`:

- без параметров выбирает самую новую установленную поддерживаемую версию;
- можно явно вызвать, например, `install.bat 3.12`;
- старые `install_python311.bat` и `install_python314.bat` оставлены как короткие
  совместимые оболочки.

Для Python 3.11 установщик использует NumPy 2.4.6; для Python 3.12–3.14 —
NumPy 2.5.2. OpenCV используется один и тот же: `opencv-python-headless 4.14.0.94`.

### Точность / защита

Этот слайдер намеренно не является вторым регулятором силы. Он меняет условия,
при которых Skin Match считается безопасным: допустимую долю ухудшившихся
измерений, cross-validation, collateral penalty и условия внутреннего refinement.

Поэтому на хорошем однородном изображении `-100`, `0` и `+100` могут дать почти
одинаковый результат: один и тот же кандидат уверенно проходит все проверки.
Разница должна проявляться прежде всего на пограничных кадрах, где сильный LUT
затрагивает фон или часть skin measurements ухудшается.


## v0.9.3 — «Точность / защита» теперь реально меняет коррекцию

В v0.9.2 этот ползунок в основном сдвигал пороги принятия кандидата. На большинстве
кадров один и тот же Skin Match проходил все варианты проверки, поэтому визуальный
результат оставался одинаковым.

Теперь ползунок управляет и **реальным бюджетом коррекции**:

- `Auto = 0` сохраняет прежнее поведение и максимум Skin Match `100%`;
- в сторону **Точность** алгоритм может проверить силы до `120%`, но такая сила
  используется только если фактический ΔE кожи продолжает уменьшаться и все
  обязательные аварийные проверки остаются пройдены;
- в сторону **Защита** верхний предел Skin Match плавно снижается до `60%`;
- одновременно заметнее меняются nonworse/p75/CV/collateral-пороги;
- в режиме Защита внутренний chroma refinement ограничивается по максимальной силе;
- catastrophic spill остаётся жёстким запретом при любом положении ползунка.

Также исправлена логика выбора near-best strength: раньше крайние значения могли
парадоксально приводить к почти тому же или даже более сильному кандидату.


## v0.9.4 — более заметный «Тени / света»

`Auto = 0` сохраняет прежнюю Tone-коррекцию.

При отклонении от Auto ползунок теперь не только меняет статистический вес
тональных измерений, но и безопасно перераспределяет уже найденную гладкую
Tone-коррекцию:

- в сторону **Тени** shadow-компонента может быть усилена примерно до 45%, а
  highlight-компонента немного ослаблена;
- в сторону **Света** highlight-компонента может быть усилена примерно до 35%,
  а shadow-компонента ослаблена;
- средние тона меняются значительно меньше;
- при сильном приоритете теней слегка расширяется допустимый безопасный диапазон
  shadow movement;
- после перераспределения всё равно проверяются общий ΔE, monotonicity, slope,
  bend и доля неухудшившихся измерений.

Сам знак коррекции ползунок не задаёт: если образец требует затемнить тени,
движение к «Тени» усиливает именно затемнение; если требуется осветлить —
усиливает осветление.

Отображаемый `ΔL*` остаётся нейтральной метрикой, поэтому имена слоёв можно
сравнивать между разными положениями слайдера.
